Structural Safety

Four verifiable guarantees

Disk utilities ask for blind trust while holding deletion APIs. Scoria removes the capability entirely so a bad rule, a model hallucination, or a bug cannot destroy data.

INVARIANT 01

It cannot delete

There is no delete, move, rename, registry-write, or shell file-operation path in the tool. Recommendations are text, not commands. The only file write is the optional HTML report path you explicitly pass to -html.

Enforced by source & PE tripwires No Write APIs
INVARIANT 02

It sends nothing by default

Network access is off by default. The optional -ai and -ai-discover analyzers send redacted, path-free payloads to OpenRouter only when you ask. Inspect the exact JSON offline first with -ai-preview or -ai-discover-preview. No telemetry, no crash reports.

Opaque IDs (c1, c2) only Offline Default
INVARIANT 03

Metadata only by default

The normal scan reads directory entries and file attributes (FILE_READ_ATTRIBUTES), never file contents. Cloud placeholders are counted without opening or hydrating them. Content duplicate verification is opt-in with -dupes and reads only same-size candidates ≥ 1 MiB.

8 KiB prefix + SHA-256 on opt-in Zero Content Reads
INVARIANT 04

It can drop privileges

-low-integrity lowers the process token to Windows Low Mandatory Integrity (S-1-16-4096) before scanning, so the OS kernel blocks writes to normal user profile directories. File report output is disabled in that mode (-html - to stdout still works).

OS-enforced write-up block S-1-16-4096

Architecture

Bounded memory from Win32 enumeration to report

Scoria never stores a per-file index of your drive in memory or a database. It streams directory entries through bounded heaps and deterministic rules.

01 · ENUMERATE

Win32 Large Fetch

Walks \\?\ paths via FindFirstFileExW with FindExInfoBasic and a bounded worker pool. Skips reparse points to prevent junction loops.

02 · FILTER

Pre-Scan Exclusions

Applies built-in sensitive rules and user exclusions during enumeration before paths enter totals, heaps, logs, or output.

03 · AGGREGATE

Bounded Rollups

Maintains top-N largest/oldest heaps, extension rollups, hard-link deduplication by file ID, and size → count maps.

04 · VALIDATE

Rules & Guardrails

Generates deterministic candidates with confidence levels while withholding protected Windows and system paths.

05 · OUTPUT

Console, JSON, HTML

Renders terminal summaries, a versioned JSON digest (version: 1), or a self-contained interactive HTML report.

Signal vs. Restraint

Explicit scope and hard boundaries

Every recommendation carries a rule ID, a priority, a confidence rating (high, medium, or low), and a plain-English reason. Confidence describes the evidence—never permission to delete automatically.

What it finds

Review Candidates
  • +
    Generated directories such as node_modules, __pycache__, .venv, build, dist, target, and obj
  • +
    Large and old files retained in bounded top-N heaps, with all protected OS and application paths withheld
  • +
    Temporary and crash-dump extensions including .tmp, .part, .crdownload, and .dmp
  • +
    Duplicate leads & verified groups: size-only leads by default, plus SHA-256 content-verified duplicate groups when you pass -dupes
  • +
    Transparent skip accounting: reparse points, permission denials, cloud placeholders, and long paths are counted separately instead of silently hidden

What it will not do

Hard Non-Goals
  • ×
    Never recommends protected paths under Windows, Program Files, restore points, $Recycle.Bin, Recovery, Windows.old, or system paging/hibernation files
  • ×
    Never reads file contents by default, and never opens or hydrates OneDrive / cloud placeholder files
  • ×
    Never phones home: no background network calls, no telemetry, no crash dumps, and no silent report uploads
  • ×
    Never lets an LLM invent paths: optional -ai ranking validates every returned ID against local rule candidates and rejects unknown IDs
  • ×
    Never tells you a file is "safe to delete": it reports what looks unused and why, leaving every action to you

Workflows

Quick start & common recipes

Run scoria.exe with no arguments (or double-click it) to launch guided interactive mode, or pass flags in PowerShell for repeatable workflows.

1. Standard & interactive scans

Metadata Only

Scan a user profile or launch guided setup with duplicate/AI analysis, an HTML report, and post-scan priority/size sorting.

scoria -root C:\Users\me
scoria -interactive

2. Self-contained HTML report

Browser View

Generate an offline, zero-dependency HTML report with interactive priority/size sorting.

scoria -root C:\Users\me -html scoria-report.html
scoria -root C:\Users\me -html - -open=false > report.html

3. Content-verified duplicates

Opt-In Content Read

Hashes 8 KiB prefixes then full contents only for same-size candidates ≥ 1 MiB.

scoria -root C:\Users\me -dupes -sort=size

4. Inspect AI payloads offline

Zero Network

Verify the exact redacted, path-free JSON before ever configuring an API key.

scoria -root C:\Users\me -ai-preview
scoria -root C:\Users\me -ai-discover-preview

Privacy by Default

Enumeration-time exclusions & sensitive presets

Exclusions are applied while walking directories—excluded subtrees are never descended into and never enter byte totals, heaps, JSON digests, or reports.

Always-on sensitive preset

Scoria automatically withholds credential stores, keys, password-manager vaults, browser profiles, and cryptocurrency wallets from enumeration and recommendations.

.ssh *.kdbx *.pem *.key wallet.dat Browser Profiles Password Managers Crypto Wallets

Default config lookup

When -exclude-file is omitted, Scoria automatically loads %APPDATA%\Scoria\exclusions.txt if it exists (and prints the rule count to stderr). It never creates the file or directory. Pass -no-config for a clean run with only built-in rules and explicit flags.

Example %APPDATA%\Scoria\exclusions.txt

One rule per line: dir, glob, ext, or name. Relative directories resolve against the config file's folder. 

# %APPDATA%\Scoria\exclusions.txt
dir  D:\Projects\archive
dir  "C:\Users\me\AppData\Local\Old App"
glob *.bak
ext  .log
ext  .tmp
name Thumbs.db

Don't Trust, Verify

Auditable read-only evidence

Scoria's read-only guarantee is enforced in CI on every push and release—both at the Go source level and by inspecting the compiled Windows PE binary.

1. Source write-API tripwire

Every CI run scans cmd/ and internal/ and fails the build if any destructive Win32, NT, shell, or registry symbol appears anywhere in the scanner:

DeleteFileBlocked
MoveFileBlocked
SHFileOperationBlocked
NtSetInformationFileBlocked
RegDeleteKeyBlocked
GENERIC_WRITEBlocked

Scanner file handles use FILE_READ_ATTRIBUTES only.

2. Reproducible build & PE import inspection

Build from source with zero C dependencies or inspect the static import table of any release binary using the included tools/imports verifier or dumpbin /imports: 

$env:CGO_ENABLED = "0"
go build -trimpath -ldflags="-s -w" -o dist/scoria.exe ./cmd/scoria
go run ./tools/imports dist/scoria.exe

Releases publish scoria.exe alongside SHA256SUMS and IMPORTS.txt.
